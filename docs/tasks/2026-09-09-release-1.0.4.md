# 1.0.4 构建修复与发布

## 根因和修复计划

失败运行：`34330047647`，提交 `a786e33`。依赖安装、88 项测试及 Docker 镜像构建成功；容器验收在 `docker/smoke.mjs` 检查 `asset-licenses.txt` 时失败。该检查仍要求已移除的 FluidR3/MIDI.js 音源作者 Frank Wen 和 CC BY 3.0 US，而实际分发已改为 Karoryfer/tonejs-instruments 的 CC BY 3.0 Unported 萨克斯采样。

1. 将现有公开静态资源验收提取为可复用函数，先用仓库实际静态资源复现旧断言失败。
2. 根据已固定的采样来源修正断言，补齐萨克斯来源、完整许可、样本映射及实际 MP3 验收。容器检查与本地测试共用函数；不删除许可证检查、不新增依赖。
3. 运行本地测试、构建及许可清单检查，独立复查并推送修复；等待精确提交的 GitHub Actions 全部成功。
4. 构建通过后更新 package、锁文件、使用文档为 1.0.4；更新 Docker 文档中的旧萨克斯说明，创建版本提交与 v1.0.4 标签。
5. 确认 main 与版本标签的构建/发布成功，核对 Docker Hub 的 1.0.4、1.0、latest 标签指向同一版本；发布 GitHub Release。

## 验证和发布结果

- 旧验收函数在仓库实际静态资源上复现同一 `asset-licenses.txt` 错误；修复后通过。
- 新增 5 项验收回归：正常静态资源、署名丢失、完整萨克斯许可缺失、无效延音循环、MP3 被 HTML 回退页替代。
- 本地 93 项测试全部通过，生产构建、许可证清单检查、语法与差异检查通过。
- 完整容器识谱与发布由 GitHub Actions 验收；版本发布信息和镜像摘要记录在 [1.0.4 Release](https://github.com/jianqiao0313/easy-score/releases/tag/v1.0.4)。
